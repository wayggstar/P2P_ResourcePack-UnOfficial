# P2P_ResourcePack

Instant P2P의 **방 만들기 / 방 설정 변경 → 리소스팩 설정**에서 URL, ZIP 파일, 방장의 활성 리소스팩을 참가자와 공유할 수 있는 비공식 Fabric 애드온입니다.

## 설치

- Minecraft **26.3**, Java **25 이상**
- Fabric Loader **0.20.1 이상**, Fabric API **0.166.2+26.3**
- **Instant P2P 1.7.3 (26.3용)**
- 방장의 `mods` 폴더에 `P2P_ResourcePack-26.3-0.3.0.jar`를 추가합니다.
- 참가자는 Instant P2P로 접속하며, 이 애드온은 추가 설치할 필요가 없습니다. 기본 Minecraft 서버 리소스팩 패킷을 사용합니다.

## 사용 방법

1. 싱글플레이에서 Instant P2P의 **커스텀 방 만들기** 또는 열린 방의 **방 설정 변경**을 엽니다.
2. **리소스팩 설정**을 눌러 공유 방식을 선택합니다.

| 공유 방식 | 설정 방법 |
| --- | --- |
| 공유 안 함 | **적용**을 눌러 이 애드온이 방에 전송한 팩을 제거합니다. |
| URL 직접 입력 | HTTP(S) ZIP 다운로드 주소를 입력하고 **ZIP 확인**을 누릅니다. 같은 주소의 ZIP이 바뀌었다면 다시 확인합니다. |
| ZIP 파일 직접 업로드 | ZIP을 선택하거나 업로드 화면에 끌어놓습니다. 검증이 끝나면 **mcpacks.dev에 공개 업로드**를 누릅니다. |
| 방장의 활성 리소스팩 공유 | 감지된 목록에서 공유할 팩을 체크합니다. **목록 새로고침**으로 현재 활성 팩과 크기를 다시 확인할 수 있습니다. |

3. 비공개방에서는 **리소스팩 필수 적용**을 켤 수 있습니다. 필수 팩을 거절하거나 적용에 실패한 참가자는 접속이 해제됩니다. 공개방은 참가자 선택 적용만 지원합니다.
4. **적용**을 누르면 열린 방과 앞으로 열 방에 설정이 반영됩니다. **취소** 또는 ESC로 미저장 설정을 버릴 수 있습니다.

### 참가자의 적용 선택

- 처음 접속하거나 방장이 공유 목록을 변경하면 **적용**과 **건너뛰기**가 있는 팝업이 표시됩니다. 선택은 목록 전체에 적용됩니다. 우선순위가 가장 높은 팩이 맨 위에 표시됩니다.
- 팝업과 안내 문구는 참가자의 Minecraft 언어 설정을 따릅니다. 한국어와 영어를 지원하며, 그 외 언어 설정에서는 영어를 표시합니다.
- 공개방에서 **건너뛰기**를 누르거나 응답을 하지 않아도 접속을 유지합니다. 비공개방에서 필수 적용을 켜면 **적용**과 **나가기**가 표시됩니다. 선택과 팩 적용 응답에는 각각 3분이 주어집니다.
- 참가자 클라이언트에서 서버 리소스팩을 **묻기**로 설정했다면 다운로드 전에 Minecraft의 서버 팩 확인창이 추가로 표시될 수 있습니다.
- 팩 이름은 로컬 파일·폴더 이름 또는 URL의 ZIP 파일명에서 가져옵니다. 저장된 팩에 이름 정보가 없으면 **리소스팩**으로 표시됩니다. 활성 팩을 다시 적용하면 현재 이름을 저장합니다.

### 공유 목록 갱신

- 방장의 활성 팩이나 파일이 바뀌면 **리소스팩 설정 → 목록 새로고침 → 적용**을 누릅니다. 목록 새로고침에서는 현재 활성 팩과 크기를 확인할 수 있습니다. 폴더의 크기는 압축 전 파일 크기 합계입니다.
- 새 목록을 모두 준비하고 검증한 뒤 접속자에게 다시 적용 여부를 묻습니다. 준비나 업로드에 실패하면 직전에 검증한 목록을 유지합니다.
- **공유 안 함 → 적용**을 선택하거나 활성 팩의 체크를 모두 해제하고 적용하면 이 애드온이 전달한 팩을 방에서 제거합니다.

설정은 `config/p2p_resourcepack.json`에 저장되며 같은 클라이언트에서 여는 방에 공통으로 적용됩니다. 예전 형식에 저장된 공유 URL은 **URL 직접 입력**으로 불러옵니다.

## 작동 원리

1. **방장이 팩을 준비합니다.** URL 모드에서는 입력한 주소에서 ZIP을 내려받아 검사합니다. 직접 업로드는 선택한 ZIP을 사용합니다. 활성 팩 공유는 Minecraft의 `PackRepository`에서 활성화된 로컬 팩 중 체크한 것만 선택합니다. ZIP의 원본 바이트를 유지하고 폴더는 임시 ZIP으로 압축합니다.
2. **로컬 팩을 호스팅합니다.** 업로드가 필요한 ZIP은 mcpacks.dev의 공개 다운로드 주소에 올립니다. 방장의 애드온이 그 주소에서 ZIP을 다시 내려받아 원본과 SHA-1이 일치하는지 확인합니다. 같은 파일에 대해 검증된 주소가 있으면 재사용합니다. 서로 다른 팩은 최대 세 개씩 동시에 준비하며 화면에 완료 개수가 표시됩니다.
3. **방장의 내장 서버가 적용 여부를 묻습니다.** 참가자는 Minecraft 기본 팝업에서 이름과 우선순위를 확인합니다. 버튼은 참가자의 선택을 내장 서버에 전달합니다. 공유 목록이 새로 적용되면 이전 팝업의 선택은 만료됩니다.
4. **참가자의 Minecraft가 팩을 내려받습니다.** 참가자가 **적용**을 누르면 방장의 내장 서버가 팩별 URL과 SHA-1을 기본 리소스팩 패킷으로 전달합니다. 참가자는 해당 웹 주소에서 각 ZIP을 내려받아 방장과 같은 우선순위로 적용합니다.

## 동작 범위

- 팩 하나당 ZIP 크기는 **100 MiB 이하**이며, ZIP 최상위에 `pack.mcmeta`가 있어야 합니다.
- 활성 팩 공유는 `resourcepacks` 폴더에서 활성화한 ZIP과 폴더형 팩을 대상으로 합니다. 기본 제공 팩, 서버에서 내려받은 팩, 심볼릭 링크를 사용하는 소스는 공유 범위에서 제외됩니다.
- 팩 검증은 ZIP 구조와 SHA-1을 확인합니다. 텍스처 및 셰이더 호환성은 사용하는 클라이언트에서 확인해야 합니다.

## 빌드

Java 25를 설치하고, 원본 JAR을 `libs/instant-p2p-1.7.3.jar`에 넣습니다.

```sh
./gradlew build
```

빌드한 JAR은 `build/libs/P2P_ResourcePack-26.3-0.3.0.jar`에 생성됩니다.

- `./gradlew test`는 기존 설정 호환, 목록 우선순위, 폴더 내용 변경에 따른 ZIP 갱신, 원본 바이트 업로드, SHA-1 캐시 재사용, 병렬 업로드, 전송 순서 유지, 공개방 강제 적용 방지와 참가자 선택 유효성을 검사합니다. 업로드 테스트는 로컬 HTTP 서버를 사용합니다.
- `./gradlew runClient -PsmokeTest`는 Minecraft 26.3에서 방 설정 진입, 방 제목 유지, 공유 모드 전환, 공개방의 필수 적용 비활성화, 기본 팝업의 언어·팩 우선순위·버튼 동작, 활성 ZIP·폴더 목록, 업로드 버튼과 바닐라 팩 적용 순서를 확인합니다. 검증용 모드는 배포 JAR에 포함되지 않습니다.
- 0.3.0의 빌드, 자동 테스트 9개, Minecraft 화면·팩 순서 검증이 통과했습니다. 실제 mcpacks.dev 공개 업로드와 두 계정 간 P2P 전송 및 참가자 선택은 미검증입니다.

## mcpacks.dev 업로드

- 공개 업로드는 **mcpacks.dev (Obsidian Servers)**를 사용합니다.
- [공식 API 문서](https://mcpacks.dev/docs/api)에 따라 multipart `file` 필드와 선택적 `management_password`를 사용합니다. API 키는 필요 없습니다.
- 직접 업로드는 **공개 업로드** 버튼을 눌렀을 때 시작합니다. 활성 팩은 **적용**을 눌렀을 때 필요한 파일을 업로드합니다.
- 검증한 파일의 임시 사본을 업로드하며, 이후 반환된 URL에서 다시 받은 파일의 해시까지 확인합니다. 선택 이후 원본이 바뀌면 다시 선택해야 합니다.
- 직접 업로드 성공 후 **적용**을 누르면 방 설정이 바뀝니다. 취소나 공유 해제 후에도 이미 업로드한 파일은 서비스에 남습니다.
- 파일은 외부 서비스의 공개 다운로드 주소에 올라가며 보관/만료 정책은 해당 서비스에 따릅니다. 영구 보관을 보장하지 않습니다.
- 관리 비밀번호와 서비스 응답(`manage_url` 포함)은 `config/p2p_resourcepack_uploads/upload-*.json`에 저장합니다. 관리/삭제가 필요하면 이 파일의 정보를 사용하세요. 이 파일은 다른 사람에게 공유하지 마세요. POSIX 시스템에서는 소유자만 읽고 쓸 수 있도록 저장합니다.
- 게임 재시작 후에도 SHA-1이 같은 파일은 업로드 기록의 다운로드 주소를 다시 검증해 재사용합니다. 주소가 삭제·만료되어 HTTP 404 또는 410이 반환되거나 내려받은 파일의 해시가 다르면 다시 업로드합니다.
- 파일 선택 창은 Minecraft 26.3에 포함된 SDL을 사용합니다. 선택 창이 지원되지 않는 환경에서는 ZIP 끌어놓기를 사용할 수 있습니다.

## 리소스팩 보안

- Minecraft2Shell은 Java Edition의 폰트 라이브러리 취약점입니다. 공식 런처를 쓰는 방장과 참가자는 게임을 모두 종료한 뒤 런처를 재시작해 수정된 라이브러리를 받으세요. 서드파티 런처에서는 해당 인스턴스가 Mojang의 수정된 라이브러리를 사용하는지 확인하세요. [Mojang Java 기술 책임자 공지](https://x.com/slicedlime/status/2125288742382453097)
- 패치 확인 전에는 출처를 모르는 리소스팩을 설치하거나 불러오지 마세요. 방장은 검토한 팩만 공유하세요. 공개방에서는 참가자가 팩을 건너뛰어도 접속할 수 있습니다.
- 이 애드온은 ZIP 구조와 파일 무결성을 검사합니다. 악성 파일 탐지와 클라이언트 라이브러리 업데이트는 각각 별도로 필요합니다.
